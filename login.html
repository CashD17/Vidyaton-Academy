Where a real backend is needed
  • Sign-in: passwords must be hashed on a server (e.g. Argon2/bcrypt) and checked there. Here, demo accounts sit in your browser’s localStorage in plain text.
  • Sessions: a real server issues secure, expiring session tokens (httpOnly cookies / JWT). Here the “session” is just a browser flag anyone could edit.
  • Roles: student / parent / administrator permissions must be enforced on every API route, not just by hiding pages.
  • Guardian linking: a real system verifies the guardian’s email, records consent, and may apply children’s-privacy rules (e.g. GDPR / COPPA). Here, a code or a matching email is enough.
  • Admin accounts: should be invited or created by existing admins, with 2-factor sign-in.
  • Data & payments: grades, attendance and payments must come from a database and a payment provider. Everything on the dashboards is fictional.
